# Engineering sandbox policy

This repository is an **isolated sandbox** used to build `m9-audit-kit` and to validate
GitHub mechanics. It is deliberately separated from production, client and M9 core
repositories, which are never modified from here.

## What this repository is

- A real, usable repository-governance audit tool.
- A place to practise review, CI, releases and co-authorship safely.

## What this repository is not

- It is **not** a badge farm.
- It does **not** accept empty, duplicated or automated bulk pull requests.
- It does **not** use secondary or fake accounts, vote rings or auto-accepted answers.

## Operating rules

1. **Substantive changes only.** Every pull request delivers a check, a fix, a refactor or
   a documentation improvement, with tests where applicable.
2. **Human pacing.** At most four merges per day, with human review of each diff.
3. **Honest co-authorship.** `Co-authored-by` is used only for real, consenting
   contributors with verified emails.
4. **Discussion participation.** Answers are posted only where they are relevant, follow
   the host repository's code of conduct, and are never self-accepted or vote-manipulated.
5. **Protected repositories.** Praedia, Livia, Chiara, FSI Group, M9-Team, the `m9giu`
   profile repository and all client repositories are out of bounds.

## Why

GitHub's Acceptable Use Policies prohibit automated excessive bulk activity, fake accounts
and inauthentic interactions. This sandbox is designed to stay clearly on the right side
of those rules while still producing useful engineering work.
